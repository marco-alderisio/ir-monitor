            <div class="field field--name-body field--type-text-with-summary field--label-hidden field--item"><p><strong>Number:</strong> AL26-029<br /><strong>Date:</strong> November 17, 2026</p>

<h2>Audience</h2>

<p>This Alert is intended for <abbr title="information technology">IT</abbr> professionals and managers.</p>

<h2>Purpose</h2>

<p>An Alert is used to raise awareness of a recently identified cyber threat that may impact cyber information assets, and to provide additional detection and mitigation advice to recipients. The Canadian Centre for Cyber Security ("Cyber Centre") is also available to provide additional assistance regarding the content of this Alert to recipients as requested.</p>

<h2>Details</h2>

<p>The Canadian Centre for Cyber Security (Cyber Centre) is aware of a critical vulnerability affecting Java <span class="nowrap">runtimes<sup id="fn1-rf"><a class="fn-lnk" href="#fn1"><span class="wb-inv">Footnote </span>1</a></sup>.</span></p>

<p><span class="nowrap"></span>Tracked as CVE-2026-114938<sup id="fn2-rf"><a class="fn-lnk" href="#fn2"><span class="wb-inv">Footnote </span>2</a></sup>, this vulnerability is classified as a Heap-based Buffer Overflow [CWE-122]<sup id="fn3-rf"><a class="fn-lnk" href="#fn3"><span class="wb-inv">Footnote </span>3</a></sup> that affects the Base64 standard Java library. Known as “Java4Shell”, the vulnerability could be exploited remotely without authentication by sending specially crafted base64 data to Java processes running on x86-64 processors that contain AVX-512 Vector Byte Manipulation Instructions (VBMI) hardware. Successful exploitation could result in memory corruption, disclosure of sensitive information, process crashes or arbitrary code execution in affected applications or services.</p>

<p>Oracle has released a security advisory addressing this vulnerability<sup id="fn4-rf"><a class="fn-lnk" href="#fn4"><span class="wb-inv">Footnote </span>4</a></sup>. Organizations should identify affected systems and apply applicable vendor updates as soon as they become available.</p>

<p>The Cyber Centre is not aware of active exploitation at this time, but that can change quickly.</p>

<h2>Suggested actions</h2>

<p>The Cyber Centre strongly recommends that organizations identify affected Java applications and update vulnerable components to an appropriate fixed release:</p>

<p>The Cyber Centre recommends that organizations:</p>

<ul><li>Inventory Java Environments. Audit all applications to identify active Java runtimes, including vendor, full build version<sup id="fn5-rf"><a class="fn-lnk" href="#fn5"><span class="wb-inv">Footnote </span>5</a></sup>.</li>
	<li>Update affected Java installations immediately to a fixed, supported release.</li>
	<li>Prioritize Internet-facing systems and applications.</li>
	<li>Identify third-party products, appliances and containers that include vulnerable Java components<sup id="fn6-rf"><a class="fn-lnk" href="#fn6"><span class="wb-inv">Footnote </span>6</a></sup>.</li>
	<li>Where immediate remediation is not feasible, organisations should consider isolating internet-facing applications from public networks until a fix can be applied.</li>
	<li>Consider disabling JVM support for AVX-512 by using JVM flag <strong>-XX:UseAVX=2</strong> if you cannot patch.</li>

	<li>Monitor for potential compromise by reviewing web server, application, authentication, and endpoint logs for suspicious activity.</li>
	<li>Continuously monitor third-party vendors for security updates, including appliances, applications and services that bundle Java, and apply applicable patches without delay.</li>
